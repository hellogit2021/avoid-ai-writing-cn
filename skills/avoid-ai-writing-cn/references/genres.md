# 体裁决策矩阵

改写前先判断体裁。不同体裁对语气、结构和"能改什么、绝不能动什么"的要求不同——**不要用同一套"人味"标准处理所有文本**。给 API 文档加"我个人觉得"，和给随笔套模板一样假。

| 体裁 | 默认处理 | 绝不能新增（红线） | 必须保留 |
|---|---|---|---|
| **个人叙事 / 观点 / 随笔** | 保留第一人称、混合情绪和作者习惯；可调整节奏 | 来源、身份、经历、医疗/法律/财务信息、指控——任何可能伤害当事人的信息 | 原有经历、立场、人物关系、事件顺序 |
| **通用说明 / 商务** | 清楚、具体、克制：先说对象、动作、结果 | 事实、数字、效果承诺、案例、因果判断 | 业务范围、适用对象、限制条件、已有数据 |
| **营销 / 品牌** | 可保留合理的宣传语气，但删掉空泛夸张 | 指标、排名、奖项、背书、客户反馈、市场表现 | 已有卖点、品牌定位、限定条件、可验证主张 |
| **技术文档 / README** | 中性直接，优先可操作性与扫描效率 | 功能、参数、性能数据、兼容性、实现细节 | 术语、命令、代码、标题层级、列表、接口行为 |
| **学术 / 论文 / 审稿回复 / 基金申请** | 保持正式、精确和证据边界；基金文本可保留有依据的愿景 | 事实、数据、结果、公式、引用、前期基础、合作信息 | 学术语体、论断与证据的对应、必要限定、术语、结构、所有数字与引用 |
| **法律 / 百科 / 说明书** | 保持正式、精确和必要限定，不强行口语化 | 事实、来源、引语、定义、结论、解释 | 引用、限定词、定义、固定表达、专业术语 |
| **版本说明 / 迁移指南** | 保留变更关系和结构，让读者能追踪版本差异 | 版本号、日期、变更原因、兼容性结论、引文内容 | 版本、改动关系、迁移步骤、原始引文 |

## 事实边界：四条硬规则

1. **非个人叙事体裁一律不补写事实。** 不补原文没有的日期、地点、数字、人物、来源、引语、经历、因果或评价。
2. **个人叙事也默认不补。** 本插件的立场是"只删减和锐化，不添加"（见 SKILL.md「重写原则」）。个人叙事允许的只有：把原文已有的抽象评价落到原文已有的具体处、把原文已有的态度写实——**不是补新的场景或感受**。
3. **示例里的演示细节不能当依据。** 本技能示例中为了演示"抽象如何变具体"而构造的细节，只说明改写方向；改写用户文本时不得据此补写事实。
4. **中性体裁不要硬塞人味。** 学术、技术、法律、百科类文本里，中性平实就是正确的人类声音。

> 可选升级（当前**未启用**）：如果希望个人叙事允许补低风险细节（日常场景、感受、偏好），必须配套一个「待核实内容」输出——终稿后逐项列出"新增：<内容>（原文未提供）"。没有这个配套机制就不要放开，否则等于允许编事实。

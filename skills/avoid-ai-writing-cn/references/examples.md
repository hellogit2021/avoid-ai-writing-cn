# 段落级与完整对照示例

用来校准"改到什么程度算够"。同一个 tell 出现在段落尺度时，比单个词更难发现。

## 五组段落级对照

**1. 跨句变体的"不是……而是……"**——否定句和肯定句分在两句话里：

```
改写前：这次改版不是简单的界面调整。它改的是背后的权限模型。
改写后：这次改版动的是权限模型。
```

**2. 重复的结尾句**——同一个 closer 在每个小节后都出现一次：

```
改写前：
本轮修复了导出乱码。
这才是关键。
同时把日志级别降到了 info。
这才是关键。

改写后：
本轮修复了导出乱码，并把日志级别降到 info。
```

**3. "……，+ 尾巴"式升华**——把英文 -ing 式的那种升华挂在事实后面：

```
改写前：这次重构拆掉了三处重复的取数逻辑，彰显了团队对代码质量的坚持，也为后续扩展奠定了基础。
改写后：这次重构拆掉了三处重复的取数逻辑。
```

**4. 名词化空转**——动词被塞进名词里，再配一个万能动词：

```
改写前：本次迭代对登录流程进行了优化，实现了响应速度的提升，后续将进行监控能力的建设。
改写后：这次改版把登录流程做快了，接下来要补上监控。
```

**5. 无主句**——不说是谁做，读起来像公告：

```
改写前：相关配置需要进行检查，如存在冲突则需进行清理。
改写后：检查一下配置，有冲突就清掉。
```

**6. 默认反驳姿态**——像在回答一个文中根本没出现的质疑：

```
改写前：我并不是说这次调整失败了。有人可能会觉得这是在找借口，但事实恰恰相反：问题不在执行力，而在排期。
改写后：这次调整没失败。问题出在排期上。
```

（三种防御句式在这里同时出现：防御式声明、假想对手、反驳式转折。改写只做一件事——**把防御改成陈述**，主张一条不动。）

## 完整示例（从原文到终稿）

**原文**

> 在当今快速迭代的 AI 时代，我们不禁要问：什么才是真正的效率？答案或许并不复杂。这次重构不是一次简单的代码调整，而是对研发协作方式的一次系统性升级。我们拆掉了三处重复的取数逻辑，实现了构建时间的显著降低，彰显了团队对工程质量的坚持。更关键的是，它为我们后续的规模化扩展奠定了基础。可以说，这是一次值得记住的改变。

**命中的痕迹**

假设场景开场（"在当今……的时代"）／反问开场＋自答（"我们不禁要问……答案或许并不复杂"）／跨句"不是……而是……"／名词化空转（"实现了……的显著降低"）／"……，+ 尾巴"式升华（"彰显了……"）／"更……的是"／假深刻收尾（"值得记住的改变"）。

**终稿**

> 这次重构拆掉了三处重复的取数逻辑，构建时间降了不少。

**改动说明**

删开场铺垫与自答式反问；"不是简单调整，而是系统性升级"合并成一句直陈；"实现了构建时间的显著降低"还原成动词；删掉"彰显""奠定基础""值得记住"三处升华，结束在具体事实上。

**一条硬边界**：原文只说"显著降低"，没有给数字，所以终稿不能写"从 12 分钟降到 4 分钟"——那是编事实。如果作者手上有这个数字，换上去才是更好的改法，但这必须由作者提供。
